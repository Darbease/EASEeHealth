EASE eHealth — 5-Minute Demo Script
====================================

SETUP: Anvil + services + dashboard running (make anvil, make services, make dashboard)


[0:00–0:40] THE PROBLEM
────────────────────────
Show dashboard homepage.

"Prior auth is the most hated process in American healthcare.
A physician orders a $38K coronary stent. Faxes it. A nurse reviews it
3-7 days later. Maybe approves. Maybe the fax gets lost. The patient waits.

72% of physicians say delays cause adverse outcomes. $528 billion a year
in admin costs. The problem: everyone maintains their own version of truth.
EASE eHealth replaces trust with cryptographic verification."

Point to "Traditional vs EASE eHealth" panel. Don't read it — let them scan.
Point to stats bar: 8 workflows, 5 contracts, 3 trigger types.


[0:40–1:15] WHY CRE
────────────────────
Point to "Why Chainlink CRE" panel.

"If the payer runs the logic, providers don't trust it. If the provider
runs it, payers don't trust it. CRE runs it on a DON — nobody trusts
anyone, they verify.

Four capabilities: DON consensus on API calls, AES-GCM encryption for
HIPAA compliance, DON-signed on-chain writes, and ECDSA-authenticated
HTTP triggers. We use all four."

Point to three-trigger architecture: Cron, Log, HTTP.
"Three trigger types for three clinical urgency levels. We'll demo all three."


[1:15–2:15] SCENARIO A — CRON ($850 knee MRI)
──────────────────────────────────────────────
Click Scenario A.

1. "Reset & Deploy" — deploys 5 contracts, grants roles, seeds data.
2. "Run WF-001" — watch streaming output.
   "DON fetches encrypted EHR data, checks consent and policy on-chain,
   evaluates 6 predicates, writes 5 transactions: submit, proof, schedule
   payout, release payout, mark paid."
3. "Settle On-Chain" — watch state machine: NONE → SUBMITTED → APPROVED → PAID.

Point to on-chain state: proof hash, $850 payout, escrow drops to $999,150.
"Instant settlement. Not a 30-day paper check."


[2:15–3:15] SCENARIO B — LOG ($32,300 transfer)
────────────────────────────────────────────────
Click Scenario B.

"Event-driven. No polling. The moment a claim is submitted on-chain,
WF-007 fires automatically from the ClaimSubmitted event."

1. Reset & Deploy.
2. Run WF-007 — setup step submits claim on-chain, triggers the workflow.
3. Settle.

"It skipped submitClaim — the claim was already SUBMITTED from the trigger.
Went straight to verification and settlement. $32,300 settled reactively."


[3:15–4:10] SCENARIO C — HTTP ($38,000 cardiac CT)
───────────────────────────────────────────────────
Click Scenario C.

"Lowest-latency path. Provider signs a request with the full payload —
claim ID, procedure, amount, consent, policy — and sends it directly
to the CRE gateway. Zero delay. No EHR fetch needed."

1. Reset & Deploy.
2. Run WF-008 — show the JSON payload.
3. Settle. Watch $38,000 move through escrow.

"Three triggers, three urgency levels: HTTP for urgent, Log for reactive,
Cron for batch. A production system needs all three."


[4:10–4:40] CONTRACT EXPLORER
──────────────────────────────
Click Contract Explorer. Paste a claim ID.

Show: state PAID, proof hash 0xb8b8..., payout RELEASED, consent ACTIVE.

"Every state transition on-chain and queryable. Compliance audits that
take weeks in traditional systems take minutes. Zero PHI — only hashes,
states, and payout amounts."


[4:40–5:00] CLOSE
──────────────────
"The $528 billion question isn't whether healthcare admin can be automated.
It's whether automation can be trusted by all parties simultaneously.

8 workflows, 5 contracts, 6 services, all three CRE trigger types,
AES-GCM encryption on every confidential call, zero PHI on-chain.
Chainlink CRE makes multi-party trust possible. EASE eHealth proves it works."
